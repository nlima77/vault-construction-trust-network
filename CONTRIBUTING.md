# Contributing

We welcome serious contributions from people who care about construction documentation, AI document review, privacy, security, and tamper-evident records.

## Contribution standards

Please keep contributions aligned with these principles:

- product first, token second
- no hype or price claims
- no false affiliation claims
- no private customer data in public examples
- no unreviewed security-sensitive code
- preserve original MIT attribution where required
- explain assumptions and risks clearly

## Good first contribution areas

- construction document schema ideas
- contractor/homeowner workflow feedback
- privacy/security review
- AI document classification prompts
- proof-layer design feedback
- README/docs cleanup
- MVP issue breakdown
- sanitized demo data structure

## Pull request rules

1. Explain what the change does.
2. Explain whether it uses, copies, modifies, or derives from original Vault AI / OP Vault code.
3. Preserve copyright and license notices.
4. Avoid adding secrets, API keys, wallet keys, customer documents, or private photos.
5. Do not add token price language, investment claims, or guaranteed utility claims.
6. Keep public wording aligned with “community-led / unaffiliated unless verified.”

## Code contribution note

If future code is derived from `pashpashpash/vault-ai`, the original MIT license and copyright notice must remain included:

```text
Copyright (c) 2023 pashpashpash
```

## Security concerns

If you find a security issue, do not post customer data, secrets, exploit steps, wallet keys, or private records publicly.

Use [`SECURITY.md`](SECURITY.md) for reporting guidance.
